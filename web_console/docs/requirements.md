# G1 网页控制需求草案 v0.1

本文用于需求对齐。当前实现提供现场地图与配置编辑、模拟控制、ROS 状态观察及显式 ros_control 导航控制。用户于导航方案确认后授权接入导航准备、实时位姿/路径、单点及巡航执行。其他未勾选项仍待单独确认。

## 目标与部署边界

- 开发机：当前 Ubuntu 22.04 / x86_64 / ROS 2 Humble。
- 目标机：G1 的 PC2，Ubuntu 20.04 / aarch64 / ROS 2 Foxy。
- 部署方向：PC2 本机原生 Python 3.8 / Foxy，沿用 P1 平台配置。
- 手机、平板和电脑仅运行浏览器，通过网关访问。浏览器不接触 DDS，也不需要安装 ROS。
- 本机合成验证使用 Humble，PC2 适配使用 Foxy；页面与 HTTP/WS 协议复用，Python 依赖、ROS 适配器、Nav2 配置和 C++ 构建按目标版本验证。

## 页面划分

1. **运行总览**：连接状态、运行模式、定位状态、地图、任务选择、进度、开始/取消/放行、近期事件。
2. **导航点**：map_id、导航点名称/ID/坐标，可编辑名称/坐标、地图选点，实时采样录点待接入。
3. **巡航任务**：路线、逐站讲解、语言、等待时间、自动/人工推进配置。
4. **系统接入**：建图、定位/Nav2、运动/语音桥管理和诊断，按后端能力启用。

前端根据后端 capabilities 决定按钮状态；后台独立校验，不能以按钮是否可点击作为权限依据。

## 建议的业务规则

### 控制与连接

- 网关 HTTP 命令与状态 WebSocket 使用同一站点地址，前端以当前域名构造连接，不写死 IP 或 localhost。
- 一个后台实例负责一个机器人；首版只运行一个 Uvicorn worker。多进程部署前须引入共享租约和命令存储。
- 控制权租约有效期为 300 秒（5 分钟），页面每 5 秒续租，每次续租成功后重新计时 5 分钟。租约凭证只交给取得控制权的设备，状态广播不包含凭证。
- 手机端临时续租失败保留凭证并暂停操作，恢复前台或网络后立即核验；请求串行执行，旧请求不能覆盖新权限。明确过期后需手动重新取得，不自动抢占其他设备。页面显示“操作剩余时间”或待同步/核验状态。
- 已按确认的导航方案接入：自主巡航在页面刷新、失联或控制权到期后仍由机器人侧继续；到人工等待阶段持续等待。
- 网页摇杆若加入，则必须独立实现机器人侧失联停止检测、控制源仲裁和指令有效期。现有桥的 0.5 秒速度超时无法发现仍持续产生 Nav2 速度的网页失联。
- 状态流超过 2 秒无新快照时，界面标记过期并禁用命令；重连后先重新获取状态，不自动重发命令。
- 模拟任务与租约只存在内存中，网关重启后清空。真实任务由已有任务执行器持有，命令回执、Action UUID 与终态持久化，重启后核对运行归属；未知结果禁止重复启动。

### 任务与停止

- 开始任务：服务端检查地图、定位、Nav2、运动桥、语音桥、恢复标记及任务配置，复用现有任务执行器。
- `202 accepted` 只表示请求被接受；开始成功、完成、取消成功都由状态或最终 Action 结果确认。
- “继续”必须同时匹配 run_id 和当前 wait_id，消费后清空；过期或重复请求不能放行下一站。
- 取消绑定 run_id，后续真机适配绑定本任务 Action goal，避免影响其他客户端。
- 只有收到可信结果且 gate_closed=true、goals_terminal=true，才能显示停止收尾已确认。未知值使用 null，不推断成功。
- `STOP_UNCONFIRMED` 保留恢复标记和现有人工恢复流程；网页不自动删除标记。
- 网页取消按钮不是实体急停的替代品。
- 泛用“暂停/恢复”需要新增状态机；现有“人工等待→继续”不应包装成任意阶段暂停。

### 数据与进程

- 导航点与任务必须属于相同 map_id；复用现有 YAML 严格校验、引用检查和备份。
- 配置写入需版本号/If-Match 和原子替换，拒绝多个设备覆盖彼此修改；任务运行或存在停止恢复标记时拒绝编辑。
- 建图管理仅允许固定白名单动作和受限地图名称，管理 PID 身份、日志、操作 ID、并发互斥与退出结果；其他进程管理待接入。
- 网页不接受 shell 命令、任意文件路径、ROS topic 名称或启动参数。
- 建图与导航互斥；运行任务时拒绝切换地图或直接启停底层进程。
- PC2 版本使用原生持久化目录保存地图、配置、任务结果和命令记录；当前已读写导航点和任务文件并备份，地图只读。

## 通信和数据源

| 网页动作/数据 | 网关外部接口 | 内部接入点 |
| --- | --- | --- |
| 定位状态 | WebSocket 状态快照 | /g1_relocalization/status，检查发布与成功扫描时间戳 |
| 任务状态 | WebSocket 状态快照 | /g1_task/get_state；最终状态来自 ExecuteMission 结果 |
| 运行任务 | HTTP 命令 | /g1_task/execute_mission Action |
| 人工放行 | HTTP 命令 | /g1_task/continue Service |
| 取消任务 | HTTP 命令 | 当前任务 Action goal 取消并等待结果 |
| 机器人位姿 | 后续 WebSocket 位姿频道 | TF map → nav_base，检查时间新鲜度 |
| 地图与路径 | HTTP 地图资源 + 后续 WebSocket 增量 | 匹配的 PGM/YAML、Nav2 路径 topic（现场核对） |
| 建图/导航生命周期 | HTTP 长操作 + 状态进度 | g1_mapping.sh / g1_navigation.sh / g1_navigation_real.sh 白名单适配 |
| 导航点/任务文件 | HTTP 目录与配置 API | WaypointStore、load_missions 与现有采样工具 |

低频状态先采用 2 Hz 全量快照。后续位姿、路径、大地图、点云和视频按数据量分流，避免共用命令队列。

## 开发顺序与验收

1. **框架与需求对齐（本次）**：可运行模拟页面、接口契约、模拟任务回归、只读 ROS 边界和公共导视牌视觉规范。
2. **当前电脑的现场只读页面**：地图、TF、路径、桥和语音就绪、日志；核对所有新鲜度、单位和 frame_id。
3. **当前电脑的高层真机控制**：任务执行/取消/放行，再接入进程启停；文件编辑已单独实现；完成 HTTPS、访问权限、命令持久化与停止确认回归。
4. **PC2 原生适配（P6 源码已完成，现场待验收）**：单独准备 Python 3.8 / Foxy 依赖和 ROS/Nav2 配置，在 ARM64 编译；复用网页和接口协议，验证雷达、机器人状态、定位/Nav2 负载与断线恢复。通过前不宣称 PC2 已兼容。
5. **扩展需求**：网页遥控、视频、外网访问按确认结果实施。

验收用例至少包含：两设备争抢控制权、刷新不重复启动、失联后显示过期、旧放行请求被拒绝、末站须放行、取消仅作用于本运行、定位失效禁用控制、STOP_UNCONFIRMED 阻止继续、网关重启后恢复归属、示例数据不混入现场显示。
